Operator guide

Know what each step changes before you approve it.

Alpha software — evaluate before use

Bugs, security issues, and breaking changes can cause downtime, data loss, or missed rewards. Start with a disposable identity. Keep independent, tested backups before adopting an important node. Open source and valid signatures are not a guarantee of safety.

Before you start

QuilNode is the Mac management app. The Quilibrium node is a separate background service; qclient is its separately managed companion. Installing the app does not itself install a node or create an identity.

  • App compatibility: Apple Silicon and macOS 14 or later. Intel Macs, Windows, and Linux cannot run this app.
  • Node capacity: allow enough memory, SSD space, and reliable connectivity for the workload. Check the current Quilibrium requirements; passing the app's initial checks is not a capacity guarantee.
  • Permissions: a macOS administrator approves installation of the local service. Ordinary monitoring does not need a password.
  • Tools: the signed-node installation path does not need Xcode, Homebrew, Rust, or Cargo. Source-development builds have separate toolchain requirements.

Read the security model yourself or with a reviewer you trust. QuilNode is independent of, and not endorsed or supported by, Quilibrium Inc. or the protocol maintainers.

Download & verify

  1. Use the download page or quilnode/quilnode Releases. Read that release's compatibility notes and known issues. “Available soon” means there is no matching published installer; do not substitute a rehearsal build or a file from chat.
  2. Download the .dmg and SHA256SUMS from the same release. Keep the original filenames. Compare the DMG's SHA-256 with its exact entry in the checksum file. 
shasum -a 256 "/path/to/the-downloaded-file.dmg"

Replace the quoted path with your downloaded file. This command only reads the file. A mismatch means stop; do not open it. Matching a checksum downloaded alongside a file detects mismatched bytes, but does not independently authenticate the publisher.

Full signature and package verification

Technical reviewers can use the verifier from the reviewed source at the release's exact signed tag. Download every attached release asset into one otherwise empty directory; do not include GitHub's automatically generated source archives. From that source checkout, run: 

scripts/release/verify-release.sh "/path/to/release-assets"

The verifier uses the checked-in public keys to authenticate the signed report, feed, and DMG before mounting it read-only, then checks the delivered app and inventory. It needs the verifier's development tools, including Swift and Python 3; it does not need private keys and does not install the app. Review the source and trust anchors first. Do not add --rehearsal when verifying a public release.

Install & first open

  1. Open the verified DMG in Finder.
  2. Drag QuilNode onto the Applications folder link. Wait for the copy to finish, then eject the DMG.
  3. Open QuilNode from Applications, not from the mounted installer. The local service expects the installed app at /Applications/QuilNode.app.

When macOS blocks an unknown developer

Community-signed builds use the project's signing certificate. They are not Apple Developer ID signed or Apple-notarized. A valid project signature does not make the publisher Apple-verified.

If you have reviewed the source and release, verified the download, and choose to proceed:

  1. Try opening the installed app once.
  2. Open System Settings → Privacy & Security. Find the message about QuilNode and choose Open Anyway, if macOS offers it.
  3. Read the confirmation and authenticate if requested. Return to Applications and open QuilNode.

This is a specific app exception—not a reason to disable Gatekeeper. Stop if macOS says the app is damaged, contains malware, or will harm your computer. Do not run blanket quarantine-removal commands. See Apple's first-open guidance; managed Macs may require your administrator's help.

Set up your node

A new installation

  1. Let QuilNode setup inspect this Mac. Resolve blocked checks; do not treat “checking” as “offline.”
  2. Choose Acquire signed release. The app downloads and verifies the official node artifacts before offering installation.
  3. Read Review authorization and continue to the macOS prompt. The local service creates a restricted runtime account, installs the managed runtime, and configures its startup service and required operating-system limits.
  4. Wait for runtime validation. QuilNode installs or reuses a compatible managed qclient; do not install an unrelated copy into the app bundle.
  5. Choose an identity, then complete network readiness. A running process is not proof of enrollment or rewards.

Keep, import, or create an identity

  • Keep detected identity: retain the existing complete keyset and create managed rollback protection. If QuilNode does not detect an installation you expect, stop and review its location; do not create a replacement identity as a workaround.
  • Import an existing keyset: select the folder containing both config.yml and keys.yml. Never mix files from different backups. The local service checks the package and detects its format before activation.
  • Create a new identity: generate a new local identity with the verified runtime and client. A new identity does not inherit an old identity's seniority.

For legacy, including pre-.25, packages, keep an untouched copy before migration. Review the detected format and transaction plan. The installed runtime performs the required migration; do not hand-edit private-key fields. A changed network identity does not by itself prove loss of legacy identity continuity, and preserving files does not guarantee a particular chain seniority.

What the password authorizes

The macOS authorization prompt approves a restricted local service; QuilNode does not save your password. Routine authorized controls and signed updates can reuse that trust. Identity creation, import, activation, and recovery export deliberately require fresh approval. Changing the trusted app identity, repairing the service, or enabling a broader development-update policy can require another prompt. There is no promise of “one password forever.”

Cancel any unexpected prompt and review the operation first. No part of this setup requires disabling system protections or granting blanket Full Disk Access.
